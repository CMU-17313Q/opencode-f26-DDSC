## Requirement changes

| ID  | Original requirement (P4A)                                            | Revised requirement (P4B)                                                                                                                                         | Why it changed                                                                                                                                                                                                                                                                           |
| --- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R6  | A restored session must appear at the top of the active session list. | Within the same folder, a restored session must appear before other unpinned sessions, provided their updates precede the restoration and no later update occurs. | The existing TUI places pinned sessions first and groups other sessions by folder. A global-first guarantee conflicts with those features and with newer updates. The revision preserves the intent of making the restored conversation easy to find while respecting existing ordering. |

R1–R5 remain feasible and have observable acceptance criteria. Keeping a requirement does not mean that this submission verifies every part of it: R3 and R5 are explicitly outside the selected property coverage.

## Validation

Each property runs 100 generated examples against the real session service and database. Generator choices are explained in the test comments. These tests cover session behavior and folder ordering; they do not render the TUI or test restart/help-menu behavior.

R6 initially failed because its fixture was missing `Database.Service` (seed `711840520`, shrunk input `{"ages":[1,1],"folder":"","index":0}`). Adding `Database.node` fixed the fixture. The R6 oracle was also corrected to allow any order among peers with equal timestamps. No production changes were needed.

From `packages/opencode`:

```bash
bun test --timeout 30000 --only-failures test/session/session-archive.property.test.ts test/session/session.test.ts
bun typecheck
```

Local results: **17 tests passed, 0 failed**, including **400 generated examples**. Typechecking, lint, and formatting passed. The existing PR workflow includes these tests; each property prints a success line even with `--only-failures`. Remote PR/CI validation is still pending.
