## Requirement changes

| ID | Original requirement (P4A) | Revised requirement | Why it changed |
|---|---|---|---|
| R1 | Mouse click anywhere on a paste chip opens a read only viewer titled "Pasted text" that displays that chip's stored pasted text verbatim | A click on a paste chip opens a read only viewer titled `Pasted Text` with exactly that chip's stored text. Wrapping may change layout only. | Checkability. "Verbatim" did not separate content from layout, and the actual title is `Pasted Text`. Kept C-2, S-3, O-3. |
| R2 | The viewer never truncates content. It grows to fit short content, caps at the terminal height, and overflows into vertical scrolling if the text is too big to fit in one screen. | The viewer never drops or replaces content. It fits short content, caps at terminal height, scrolls vertically when needed, and wraps long lines. | Feasibility and checkability. A terminal cannot show all content at once, so the criterion needs reachability by scrolling. The P4A wording also omitted long line wrapping from C-11, S-13, O-15. Kept C-5, S-6, O-7, C-10. |
| R3 | Opening, viewing, and closing the viewer must not modify the prompt buffer in any manner (especially paste parts). Submitting after viewing sends exactly the same test as submitting without viewing. | Opening, viewing, and closing the viewer leaves the prompt text, paste parts, extmark ranges, and cursor offset unchanged. Submitting after viewing sends the same text. | Checkability. "In any manner" did not name the state to preserve. The criteria also omitted the cursor from O-10. Fixed the test/text typo. |
| R5 | When a prompt contains multiple paste chips, clicking one displays only that chip's pasted text. | Same requirement. Acceptance criteria clarified. | Checkability. The P4A criteria said extmarks mapped 0 and 1, but those are part indices, not extmark IDs. |

R4 kept as written. The requirement already states the observable behavior and no feasibility or checkability problem surfaced.
