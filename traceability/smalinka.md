# Traceability: Simon Malinka (smalinka)

**Target feature:** Search archived sessions (Issue #1, PR #18). The "Include archived" toggle in the home page session search bar makes the search also return archived sessions whose title matches the query. They appear after the matching active sessions and carry an "Archived" badge. Main source files:

- [`packages/opencode/src/session/session.ts`](../packages/opencode/src/session/session.ts): `listByProject` / `listGlobal` filter sessions by title (`titleSearch`) and by archived state, and `setArchived` archives and unarchives
- [`packages/app/src/pages/home/home-session-search-controller.ts`](../packages/app/src/pages/home/home-session-search-controller.ts): toggle state, one archived query per open project, merging with the active sessions
- [`packages/app/src/pages/home/home-session-search.ts`](../packages/app/src/pages/home/home-session-search.ts): `matchesSessionSearch` (filters the active sessions the page already has) and `mergeSessionSearchResults` (active first, then archived, each session once)
- [`packages/app/src/pages/home/home-sessions-view.tsx`](../packages/app/src/pages/home/home-sessions-view.tsx): toggle button and the "Archived" badge, drawn when `session.time.archived` is set

Property files:

- **Server file:** [`packages/opencode/test/session/search-archived.property.test.ts`](../packages/opencode/test/session/search-archived.property.test.ts) drives the real Session service and SQLite database. Run with `bun test test/session/search-archived.property.test.ts` from `packages/opencode`.
- **App file:** [`packages/app/src/pages/home/home-session-search.property.test.ts`](../packages/app/src/pages/home/home-session-search.property.test.ts). Run with `bun test --conditions=solid --preload ./happydom.ts src/pages/home/home-session-search.property.test.ts` from `packages/app`.

Both run in CI through `bun turbo test`, and again in their own steps of [`test.yml`](../.github/workflows/test.yml) so each property is listed by name in the log (the turbo step uses `--only-failures`, which hides passing tests).

## Requirement changes

| ID | Original requirement (P4A) | Revised requirement | Why it changed |
|---|---|---|---|
| R1 | With "Include archived" off, search never returns an archived session. With it on, matching archived sessions are returned. | With "Include archived" off, search never returns an archived session. With it on, every archived session whose title matches the query (as defined in R7) is returned, up to the per-project result limit of 100 (see R8). | Checkability and feasibility. "Matching" was not defined anywhere, so it now points to R7. "Matching archived sessions are returned" also reads as "all of them", but each project's search returns at most 100 sessions, so returning every match is not possible until R8 (truncation and "show more") is built. The part interviewees cared about stays: nothing archived when the toggle is off (S-10), and a matching archived session is found when it is on (C-2, S-2, O-2). |
| R4 (Step 3) | Archiving a session and then unarchiving it leaves the search results unchanged. | Archiving a session and then unarchiving it returns the same sessions with the same labels. The restored session moves to the top as the most recently updated one, and every other session keeps its place relative to the others. | Conflict, found by the R4 property (see Triage). The unarchive feature deliberately marks a restored session as just updated, so it appears at the top of the session list where the user can see it. An existing test checks this (`packages/opencode/test/session/session.test.ts`, "restores archived sessions, bumps recency, and leaves active sessions unchanged"). Keeping the old position would break that feature. What interviewees needed (C-5, S-5, O-5) was results that do not shuffle unpredictably, sessions that do not disappear, and labels that are correct. All of that still holds: only the session they just restored moves, and it moves to a predictable place. |
| R5 | Toggling "Include archived" on, off and on with the same query returns the same results each time it is on. | Same, as long as no session is created, renamed, archived, unarchived or deleted in between. | Checkability: the results come from live data, so if a session changes between toggles a different result is correct, not a failure. The acceptance criteria now say the sessions stay unchanged. |
| R7 | A multi-word query matches sessions whose title contains every word, in any order. | A query is split into words on whitespace. A session matches when its title contains every word as literal text (characters such as `%` and `_` have no special meaning), in any order, ignoring letter case. Archived sessions are searched in the database, which ignores case only for the ASCII letters A–Z. Active sessions are also matched against their project name. | Checkability and feasibility. The original did not say what a "word" is, whether case matters, or what happens with symbols, so a test could not decide whether "LOGIN" should find "login" or whether "%" should match everything. Interviewees would stop trusting search if it missed a session (C-10, O-10) or showed irrelevant results (O-10), so symbols are matched literally. Ignoring case for every alphabet is not feasible in the database as it is: SQLite's `LIKE` only folds A–Z, and full Unicode folding needs the ICU extension, which opencode does not ship. The page already matched active sessions against their project name, which C-8, S-8 and O-8 asked for, so the requirement records it. |
| R2, R3, R6, R8 | (unchanged) | (unchanged) | Kept as written. Each is feasible, checkable and consistent with the others. R8 is not implemented yet but can be built: the server already supports a `limit`, and the page can ask for more. |

## Triage

First run against `main` (commit `283bbb3d`). The app properties were first run against the old client matching (before it moved to `home-session-search.ts`). Every failure and how it was resolved:

| Property | Shrunk counterexample | What it showed | Outcome | Fix |
|---|---|---|---|---|
| R1 invariant | Archived session "log"; query `%` | The query is pasted into SQL `LIKE '%…%'` unescaped, so `%` (and `_`) act as wildcards and match every title. | Code bug | `session.ts`: `titleSearch` escapes `\`, `%` and `_` and uses `ESCAPE '\'`. |
| R7 model / oracle | Same as above, toggle on | Same wildcard bug. | Code bug | Same fix. |
| R1 invariant, R7 model / oracle (after the wildcard fix alone) | Archived "log"; query `log l`. Archived "50% log"; query `%  l` | A multi-word query was searched as one substring, so "log l" missed "log", and "login bug" would miss "bug in login page" (R7's own acceptance criteria). | Code bug | `session.ts`: `titleSearch` splits the query on whitespace and adds one `LIKE` per word, in both `listByProject` and `listGlobal`. |
| R4 round-trip | Two active sessions titled "log"; query `_`; restore the first | After archive and unarchive, the restored session jumped to the top because unarchiving sets `time.updated` to now. I first changed `setArchived` to keep `time.updated`. That made R4 pass but broke the existing `session.test.ts` test, which checks that this is intended. | Requirement problem (conflict) | Code change reverted. R4 revised (see Requirement changes), and the property now expects the restored session first and everything else unchanged. Also made `listByProject` order equal timestamps by ID (as `listGlobal` already does), so sessions created in the same millisecond have a fixed order. |
| R7 app invariant | Title "page bug", project "logout"; query "bug page" | The page filtered active sessions by searching for the whole query as one substring, so a reordered query missed. | Code bug | `home-session-search.ts`: `matchesSessionSearch` requires every query word, in any order. The controller now uses it. |
| R7 app metamorphic | Title "log", project "log"; query "log lo" vs "lo log" | Same bug: one word order matched and the other did not. | Code bug | Same fix. |
| R7 app metamorphic (first version) | None: passed against the buggy client code | The generator built random queries, which almost never match a multi-word title, so the word-order bug never showed up. | Wrong test | Added the R7 invariant, whose queries are built from the session's own words, and changed the metamorphic property to compare against reversed queries. Both then failed on the old code (rows above). |

Passed on the first run: R6 (server and app) and R3. R3 came with a small change: the merge now identifies a session by ID, as the requirement does, instead of by directory plus ID.

After the fixes, all eight properties pass, along with the existing `test/session/session.test.ts` and `test/server/session-list.test.ts` and the app's `src/pages/home` tests.

Known limitations, not covered by R1 to R8: archived sessions are not matched against their project name (only their title), and non-ASCII letters in archived titles match case-sensitively. Both follow from searching archived sessions in SQLite. R5 and R8 still need properties: R5 needs a test of the Solid controller, and R8 is not implemented yet.
